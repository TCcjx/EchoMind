问题症状与影响修复

前端（3 项）

问题症状与影响修复
错误详情被吞 statusText 在脚本里赋值 10 处、模板引用 0 处，接口报错的真实原因永远看不到，只有一句笼统提示 新增可折叠详情出口，失败时自动展开

五、已知限制（未改）

  • 管理接口无鉴权 — /skills/reload、/knowledge/add 等未做访问控制。加鉴权属功能新增，会改变项目行为，未擅自改动。
  • 默认凭据为演示值 — Redis 密码 echomind123。公网部署前必须替换（README 已标注）。
  • 路由降权实际不生效 — 每种 Agent 只有一个实例，降权不会改变选择结果。打分链路完整但无效果，属设计限制。
  • 测试环境依赖版本偏高 — 本机 fastapi 0.141 / pydantic 2.13 / redis 8.1，高于 requirements.txt 锁定的 0.115 / 2.10 / 5.2。实测兼容，但实测结论不能完全代表 Docker 按锁定版本部署的行为，上线前建议在容器内再跑一次。
  • chromadb 在 Windows 装不上 — chroma-hnswlib 无预编译 wheel，需 MSVC。Docker 镜像内不受影响。
  • 两套 compose 不可同时启动 — 复用容器名、网络名与端口 80/8000/8001。

六、使用提示

  • 环境目录（node_modules、dist、.venv、.idea）不入库，克隆后需重建：前端 npm install，后端 pip install -r requirements-dev.txt。
  • 若 npm install 后构建报 Cannot find module '@rollup/rollup-win32-x64-msvc'，是 npm 漏装平台原生包，显式补装即可（README 已写明）。
  • 需要自己的远端时：git remote add origin <地址>，当前仓库无 remote。
